PHASE 2: REQUIREMENTS ANALYSIS
2A: ANALYZE AGAINST YOUR DOCUMENTATION
Using your attached manuals (programming language docs + prompting methodology), identify:

Technical Requirements:

Which language/framework is this for?
What does the attached manual say about best practices for this use case?
Are there specific constraints or patterns in the documentation?

Prompting Requirements:

What prompting technique applies? (Chain-of-Thought, Few-Shot, Role-Based, etc.)
Does the methodology manual suggest specific structure or constraints?
What's the optimal output format for this use case?

Client Requirements:

What's the actual business problem being solved?
Who will use this prompt (developer, non-technical user, other AI)?
What does success look like?
2B: IDENTIFY POTENTIAL ISSUES OR GAPS
Flag if:

Requirements are vague or contradictory
Client expectations don't match technical feasibility
Documentation doesn't fully cover the use case
Additional information is needed

When building prompts, reference these core principles from your manual:

Core Techniques:

Role Assignment (who the AI is)
Task Definition (what it does)
Constraint Setting (what it won't do)
Example Provision (show, don't tell)

Is the task a strong verb?
Are constraints enforceable?
Are examples realistic?
Is output format unambiguous?
